# 공유 게시판 연결

## 현재 운영 DB에서 할 일

이미 로그인용 테이블을 만들었다면 D1 `gggcworld`의 콘솔에서 `migrations/0003_community.sql` 내용 전체를 한 번 실행합니다. 로그인용 0001·0002 파일은 다시 실행하지 않습니다. 새 SQL은 `IF NOT EXISTS`를 사용하므로 같은 게시판 SQL을 다시 실행해도 기존 글을 지우지 않습니다.

이 SQL은 `community_post`, `community_comment`, `community_vote` 세 테이블과 조회용 인덱스를 만듭니다. 새 빈 DB를 설정할 때는 0001 → 0002 → 0003 순서로 적용합니다. Wrangler 마이그레이션을 이미 사용하는 DB에서는 `npm run db:remote`로 적용할 수 있습니다. 기존 테이블을 콘솔로 직접 만든 DB는 Wrangler 마이그레이션 이력과 일치하지 않을 수 있으니 0001을 재적용하지 마세요.

## 기능

- 예시 글을 화면에서 제거하고 실제 D1 목록을 표시합니다. 기존 브라우저 체험 글은 공개 게시판으로 자동 업로드하지 않습니다.
- 공개 목록·상세 열람, 진영/카테고리/검색/추천순/페이지 이동, 로그인 회원의 글·댓글·추천 등록.
- 작성자와 진영은 로그인 세션과 회원 프로필에서 결정합니다. 요청에 다른 작성자나 진영을 넣어도 무시합니다.
- 글쓰기 `/write.html`, 상세 `/post.html?id=번호`, 수정 `/write.html?id=번호`는 각각 독립 페이지입니다. 링크를 복사하거나 브라우저에서 새 탭으로 열 수 있습니다.
- 작성자만 수정·삭제할 수 있습니다. 삭제한 글은 `deletedAt`을 설정해 공개 목록·상세에서 숨기며 DB에는 남습니다.
- 새 글은 계정당 15초 간격, 댓글은 5초 간격으로 작성할 수 있습니다. 중복 추천은 DB의 복합 기본키로 막습니다.
- 제목 100자, 본문 10,000자, 댓글 2,000자, 텍스트만 지원합니다. HTML은 실행하지 않고 텍스트로 표시합니다. 이미지 업로드는 포함하지 않습니다.
- 댓글은 최근 100개를 보여줍니다. 조회수는 상세 API를 읽은 횟수이며 고유 방문자 수가 아닙니다.
- 글 임시 저장, 저장한 글(최대 100개), 구독, 테마는 기기 내 저장입니다. 글 임시 저장은 계정별로 분리하며 서버 등록 성공 후 지웁니다.

## 확인 순서

마이그레이션 적용 및 배포 성공 후 로그인 → 새 글 등록 → 주소 직접 열기 → 새로고침 → 다른 계정/기기에서 열람 → 댓글과 추천 → 본인 글 수정 → 삭제를 확인합니다. 로그아웃 상태에서는 읽기만 가능하고, 다른 회원의 글에는 수정·삭제가 허용되지 않아야 합니다.

자동 테스트는 SQLite에서 실제 SQL과 권한·검색·페이지 이동·중복 추천·동시 글쓰기 제한을 검증합니다. 로그인 세션 서명과 로그아웃은 별도 Better Auth 테스트가 담당합니다. 브라우저 QA는 운영 계정과 분리된 임시 로컬 DB에서 수행합니다.
