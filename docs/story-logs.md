# 개인 이야기와 탐험

현재 모험 진입점은 `/adventure`입니다. 로그인과 진영 확정 후에만 5개 저장 슬롯이 표시됩니다. 빈 슬롯 → 이름 입력 및 린/레오 선택 → 수호신의 첫 조작 안내 → 맵 탐험 순서입니다. 모든 새 이야기는 이 두 시작 캐릭터 중 하나를 사용합니다. 기존 공용 탐험 위치·발견·대화는 새 이야기에 가져오지 않고 보존합니다.

D1 `adventure_story`는 소유 계정, 활성 슬롯(1~5), 제목, 시작 캐릭터, 계정 진영, 별도 난수 시드, 위치, 튜토리얼 상태, 저장 revision을 보관합니다. 슬롯 할당은 단일 SQL과 부분 UNIQUE 인덱스로 동시 생성에도 5개를 넘지 않습니다. API는 모든 목록/조회/변경에서 세션의 계정으로 소유를 검사합니다. `adventure_chunk`는 이야기별 지도와 방문 구역을 저장합니다. 구 지도의 최초 발견자 정보는 사용하지 않습니다.

`world_event_progress`의 eventId는 `story UUID:event id` 네임스페이스를 사용합니다. 다른 계정뿐 아니라 동일 계정의 다른 로그도 대화·질문 제한·중복 요청·발견 기록을 공유하지 않습니다. API 키와 계정 진영은 계정 설정이며 로그별로 복제하지 않습니다. 실제 AI 호출은 기존처럼 사용자가 명시적으로 질문을 전송했을 때만 발생합니다.

위치는 걷기를 멈춘 뒤 및 구역 전환·튜토리얼 종료·창 숨김·설정에서 나갈 때 저장합니다. 저장 요청을 직렬화하고 revision 비교로 다른 탭의 진행을 덮어쓰지 않습니다. 통신 실패 시 저장 오류를 알리고 설정의 나가기를 중단합니다. 강제 종료 순간에 아직 서버에 도착하지 않은 마지막 수 걸음은 유실될 수 있습니다. 로그 지우기는 소프트 삭제이며 UI에 ‘방금 지운 로그 복원’을 제공합니다. 활성 로그는 5개이고 복원에도 빈 슬롯이 필요합니다.

HUD: 상단 내비게이션 없음. 왼쪽 위는 실제 현재 구역의 지형·장애물과 위치 점을 그린 미니맵, 구역/전역 타일 좌표. 누르면 방문 구역 지도를 엽니다. 오른쪽 위는 설정 톱니바퀴 하나. 설정에서 전체화면, 조작키, 저장 후 로그 목록, 프로필/API 키, 광장으로 나가기를 제공합니다. 오른쪽 아래 방향패드와 안내 상자는 제거했습니다. 모바일은 스와이프, PC는 방향키/WASD입니다. 왼쪽 아래 가방은 빈 상태 안내만 제공하며 아이템 시스템은 준비 중입니다.

새 테이블은 라우트 최초 접근 때 IF NOT EXISTS로 초기화합니다. 명시적 마이그레이션은 `0008_adventure_stories.sql`로도 적용할 수 있습니다. 기존 테이블/데이터는 삭제하지 않습니다. 서버 통합 테스트는 슬롯 한도·계정 소유권·지도 시드·재개·낙관적 잠금·복원·대화 격리를 검증합니다.
