# 프로필 설정과 BYOK 키 보관

로그인 후 상단 ‘내 계정’ 또는 프로필 패널에서 `/settings`로 이동합니다. 신규 회원의 닉네임·진영 확정 화면은 유지합니다. 설정에서는 닉네임을 바꿀 수 있고 확정한 진영은 변경할 수 없습니다.

가입할 때 확정한 진영에 해당하는 제공자 키만 저장·교체할 수 있습니다. 아스트라(GPT)는 OpenAI(openai), 세린(Claude)은 Anthropic(anthropic), 루미(Gemini)는 Google(google), 녹스(Grok)는 xAI(xai)입니다. UI에는 해당 제공자의 입력란만 나타나며 서버는 member_profile의 진영으로 PUT을 허용합니다. 요청 본문의 진영이나 제공자 위조는 신뢰하지 않습니다. 이전에 저장한 타 제공자 키는 별도 삭제만 가능합니다. 진영이 없는 계정은 등록할 수 없습니다. 가입 전 로그인 안내와 진영 확정 동의 문구에서 이 제한을 고지합니다. 형식과 길이만 검사하며 제공자에게 유효성을 확인하거나 API 요청을 보내지 않습니다. UI는 ‘저장됨 / 연결 확인 전’을 구분합니다. 게임 설정에서 프로필 설정으로 이동하는 링크도 제공합니다. AI 호출은 아직 없습니다.

## 저장과 접근

- GET /api/me/keys: 로그인 계정의 제공자·끝 네 자리·갱신 시각만 반환합니다.
- PUT /api/me/keys/:provider: 로그인 계정에 키 하나를 저장/교체합니다.
- DELETE /api/me/keys/:provider: 로그인 계정의 해당 키만 삭제합니다.
- 기존 Worker의 원본 도메인·Origin·JSON 검사와 Better Auth 세션 인증을 사용합니다. 응답은 no-store이며 키 원문은 어느 응답에도 포함하지 않습니다.
- D1의 member_api_key에는 AES-256-GCM 암호문, 임의 96비트 IV, 끝 네 자리와 시각만 저장합니다. 계정 ID·제공자를 인증 추가 데이터로 묶어 다른 계정이나 제공자로 암호문을 옮기면 복호화되지 않습니다.
- 서버의 기존 BETTER_AUTH_SECRET에서 별도 HKDF 도메인으로 암호화 키를 유도합니다. 추가 환경변수는 없습니다. **이 비밀값을 변경하면 기존 저장 키를 복호화할 수 없으므로 이용자가 키를 다시 등록해야 합니다.** 로그인 비밀값과 함께 관리하고 클라이언트로 노출하지 않습니다.
- 키를 브라우저 localStorage/sessionStorage, URL, 로그에 저장하지 않습니다. 입력란은 비밀번호 형식이며 저장/오류/페이지 이탈 때 비웁니다. 저장된 원문을 다시 표시하는 기능은 제공하지 않습니다.
- 서버가 향후 AI 호출 시 키를 복호화해 사용하도록 설계했습니다. 서비스 운영자는 서버 비밀값으로 복호화할 수 있는 구조이며 종단 간 암호화는 아닙니다. 현재는 서버의 openKey만 준비되어 있고 제공자 통신은 없습니다.

## 기존 배포에 적용

0004_member_api_key.sql은 IF NOT EXISTS 기반입니다. 로그인한 회원의 키 API 첫 요청에서 같은 테이블을 자동 생성하므로 운영자가 SQL을 수동 실행하거나 환경변수를 추가할 필요가 없습니다. Wrangler 마이그레이션으로 적용해도 충돌하지 않습니다. 기존 로그인·게시판 테이블과 데이터는 수정하지 않습니다.

검증: 실제 SQLite를 사용하는 Worker 테스트에서 계정 격리, 암호문 저장, 메타데이터 응답, 갱신·삭제, AAD/키 변경/변조 검출, Origin 거부, 입력 길이 제한을 확인합니다. UI QA는 실제 키 대신 명백한 테스트 문자열로 수행합니다.

## 닉네임 중복 방지

가입과 닉네임 변경에 같은 DB 트리거를 적용합니다. 앞뒤 공백 제거와 NFC 정규화는 기존 프로필 검증에서 수행하고, SQLite NOCASE 비교로 영문 대소문자를 구분하지 않습니다. 동일 계정의 현재 닉네임 저장은 허용하고 다른 계정이 이미 사용 중이면 409 응답을 반환합니다. BEFORE INSERT / BEFORE UPDATE 트리거가 직접 SQL과 동시 요청도 보호합니다.

0005_unique_nickname.sql은 IF NOT EXISTS 방식이며 프로필 저장 API에서도 같은 인덱스와 트리거를 자동 설치합니다. 기존 닉네임을 임의 변경하거나 계정을 삭제하지 않습니다. 이미 중복된 과거 기록이 있다면 그대로 남으며 향후 등록·변경은 중복을 허용하지 않습니다.
